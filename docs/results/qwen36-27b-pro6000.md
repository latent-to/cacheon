# Qwen3.6-27B FP8 on RTX PRO 6000

Dated development results from 2026-10-14 for the separate Qwen3.6-27B arena.
These checks establish numerical-audit coverage, graph capture and capacity on
the recorded runtime. They do not register an arena, collect an upload fee,
change rewards or establish paired-replay speed and pristine quality.

## Whole-model controls

The public `cacheon check` entrypoint loaded a bundle at the `model` node in
network-disabled containers as UID/GID 65534. Preflight reopened and hashed all
77 model files and checked writable paths as that same user. The faithful and
wrong-output controls used disjoint TP1 devices; these were independent checks,
not the paired speed comparison.

| Control | Numerical result | Graph result |
|---|---|---|
| Faithful `module.forward` | PASS; five audited calls, zero violations, worst fraction 1.0 | Completed, captured=true |
| Stock output multiplied by 1.5 | FAIL; two audited calls, two violations, worst fraction 0.0 | Not run after audit failure |
| Output preserved, recurrent temporal state increased by 100 | FAIL; five audited calls, one violation, worst fraction 0.046875 | Not run after audit failure |

Retained runs are `model-identity-001`, `model-wrong-001`, and
`model-state-corrupt-002`. The first state-corruption attempt used short smoke
prompts and returned NO_DECISION because it produced no audit receipts. The
second used the same longer public request set as the faithful control.

## Context capacity

The capacity diagnostic uses the existing checker's graph engine lifecycle and
the production `_chat_input_ids` helper with this checkpoint's chat template.
Distinct request namespaces prevent cross-request prefix reuse. It checks a
single near-limit request, a two-request long-context batch and eight shorter
requests. Generated text is not graded for quality in this diagnostic.

Final run `capacity-trial-256k-003` exited 0 with every token-count assertion
passing and captured model execution:

| Batch | Input tokens per request | Output tokens per request | Result |
|---|---|---|---|
| One near-limit request | 262,126 | 16 | Completed |
| Two long requests | 131,072 | 16 | Completed |
| Eight shorter requests | 16,384 | 16 | Completed |

SGLang reserves two context positions for its request/generation limits. The
previous run used 262,128 input tokens and received 14 output tokens; its
assertion requiring 16 failed. That evidence is retained separately. The final
run accounts for the reserve without changing the configured 262,144 context.
